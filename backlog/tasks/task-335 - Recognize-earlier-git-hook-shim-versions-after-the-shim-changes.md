## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: plugins/ralph/skills/ralph-init/scripts/shipped-git-hooks.sha256 lists every git hook body ralph-init has shipped, generated from git history by tests/python/test_shipped_git_hooks.py, so migrate-plugin-hooks.sh clone can replace a known old body. It lists no shim versions. The shim, plugins/ralph/skills/ralph-init/templates/shims/git-hook, has had one version since 777119a. The first time it changes, every clone breaks at once:
- migrate-plugin-hooks.sh clone refuses every installed old shim unless it is accepted;
- preflight (migration_state in plugins/ralph/skills/ralph-run/scripts/ralph/preflight.py) reports 'shims missing in this clone' in every clone;
- shared-backlog.sh enable (cmd_enable) moves an old pre-push shim to pre-push.local, so the shim then runs the plugin pre-push body twice.

Fix: record every shipped shim version the way the bodies are recorded (for example 'shim <sha256>' lines generated by the same test), and treat a hook that matches a past shim as an outdated shim. clone replaces it with the current shim in place; preflight reports it as outdated with the clone command to run, not as missing; enable replaces it rather than moving it to pre-push.local. A hook that matches neither keeps today's behaviour. Tests can use a fabricated old shim through a test copy of the hash list.
<!-- SECTION:DESCRIPTION:END -->
